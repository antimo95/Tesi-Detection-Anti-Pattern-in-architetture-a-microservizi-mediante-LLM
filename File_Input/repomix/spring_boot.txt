1580: }
1581: function app_domain(){
1582:     D=`cf apps | grep $1 | tr -s ' ' | cut -d' ' -f 6 | cut -d, -f1`
1583:     echo $D
1584: }
1585: function deploy_service(){
1586:     N=$1
1587:     D=`app_domain $N`
1588:     JSON='{"uri":"http://'$D'"}'
1589:     cf create-user-provided-service $N -p $JSON
1590: }
1591: ### installation
1592: cd `dirname $0`
1593: r=`pwd`
1594: echo $r
1595: ## Reset
1596: cf d -f pwa-beer-catalog-service
1597: cf d -f pwa-client
1598: cf d -f pwa-eureka-service
1599: cf d -f pwa-edge-service
1600: cf ds -f pwa-eureka-service
1601: cf a
1602: cf s
1603: # build all the java apps
1604: cd $r && find . -iname pom.xml | xargs -I pom  mvn -DskipTests clean install -f pom
1605: # Eureka
1606: cd $r/eureka-service
1607: cf push -p target/*jar pwa-eureka-service  --random-route
1608: deploy_service pwa-eureka-service
1609: # Beer Service
1610: cd $r/beer-catalog-service

2741: # Bootiful Microservices with Spring Boot
2742: This example shows how to create a microservices architecture with Spring Boot and display its data with an Angular UI.
2743: Please read [Build a Microservices Architecture for Microbrews with Spring Boot](https://developer.okta.com/blog/2017/06/15/build-microservices-architecture-spring-boot) for a tutorial that shows you how to build this application.
2744: **Prerequisites:** [Java 8](http://www.oracle.com/technetwork/java/javase/downloads/jdk8-downloads-2133151.html) and [Node.js](https://nodejs.org/).
2745: > [Okta](https://developer.okta.com/) has Authentication and User Management APIs that reduce development time with instant-on, scalable user infrastructure. Okta's intuitive API and expert support make it easy for developers to authenticate, manage and secure users and roles in any application.
2746: * [Getting Started](#getting-started)
2747: * [Help](#help)
2748: * [Links](#links)
2749: * [License](#license)
2750: ## Getting Started
2751: To install this example application, run the following commands:
2752: ```bash
2753: git clone https://github.com/oktadeveloper/spring-boot-microservices-example.git
2754: cd spring-boot-microservices-example
2755: ```
2756: This will get a copy of the project installed locally. To run the client and all the servers, execute `./run.sh`, or execute the [commands in this file](https://github.com/oktadeveloper/spring-boot-microservices-example/blob/master/run.sh) manually.
2757: ```bash
2758: r=`pwd`
2759: echo $r
2760: # Eureka
2761: cd $r/eureka-service
2762: echo "Starting Eureka Service..."
2763: mvn -q clean spring-boot:run &
2764: # Beer Service
2765: echo "Starting Beer Catalog Service..."
2766: cd $r/beer-catalog-service
2767: mvn -q clean spring-boot:run &
2768: # Edge Service
2769: echo "Starting Edge Service..."
2770: cd $r/edge-service
2771: mvn -q clean spring-boot:run &
2772: # Client
2773: cd $r/client
2774: npm install
2775: echo "Starting Angular Client..."
2776: npm start
2777: ```
2778: The primary example (without authentication) is in the `master` branch. A pure Spring Security OAuth implementation is in an `oauth` branch, and an example with the Stormpath SDK is in the `okta` branch. Both branches use the Okta Sign-In Widget on the front end.
2779: ### Spring Security OAuth
2780: Okta implements the [OAuth 2.0](https://oauth.net/) protocol for its API. This means you can use libraries like [Spring Security OAuth](http://projects.spring.io/spring-security-oauth/) to provide single sign-on to your applications.
2781: To check out the branch that uses Spring Security OAuth, run the following command.
2782: ```bash
2783: git checkout oauth
2784: ```
2785: The code in the `oauth` branch is described in [Secure a Spring Microservices Architecture with Spring Security and OAuth 2.0](https://developer.okta.com/blog/2018/02/13/secure-spring-microservices-with-oauth).
2786: > The changes required to move from the Stormpath SDK to Spring Security OAuth can be viewed in [pull request #8](https://github.com/oktadeveloper/spring-boot-microservices-example/pull/8/files).
2787: ### Create Applications in Okta
2788: If you don't have one, [create an Okta Developer account](https://developer.okta.com/signup/). After you've completed the setup process, log in to your account and navigate to **Applications** > **Add Application**. Click **Web** and **Next**. On the next page, enter the following values and click **Done**.
2789: * Application Name: `Spring OAuth`
2790: * Base URIs: `http://localhost:8081`
2791: * Login redirect URIs: `http://localhost:8081/login`
2792: You need to add a `roles` claim to your ID Token, so your groups in Okta are translated to Spring Security authorities. In your Okta developer console, navigate to **API** > **Authorization Servers**, click the **Authorization Servers** tab and edit the default one. Click the **Claims** tab and **Add Claim**. Name it "roles" and include it in the ID Token. Set the value type to "Groups" and set the filter to be a Regex of `.*`.
2793: Change `security.oauth2.*` properties in the following files to enter your client ID and client secret.
2794: * [edge-service/src/main/resources/application.properties](../../tree/oauth/edge-service/src/main/resources/application.properties)
2795: * [beer-catalog-service/src/main/resources/application.properties](../../tree/oauth/beer-catalog-service/src/main/resources/application.properties)
2796: You can also create a `~/.okta.env` file to override the properties in these files.
2797: ```bash
2798: #!/bin/bash
2799: # Okta with JHipster
2800: export SECURITY_OAUTH2_CLIENT_ACCESS_TOKEN_URI="https://{yourOktaDomain}.com/oauth2/default/v1/token"
2801: export SECURITY_OAUTH2_CLIENT_USER_AUTHORIZATION_URI="https://{yourOktaDomain}.com/oauth2/default/v1/authorize"
2802: export SECURITY_OAUTH2_RESOURCE_USER_INFO_URI="https://{yourOktaDomain}.com/oauth2/default/v1/userinfo"
2803: export SECURITY_OAUTH2_RESOURCE_TOKEN_INFO_URI="https://{yourOktaDomain}.com/oauth2/default/v1/introspect"
2804: export SECURITY_OAUTH2_CLIENT_CLIENT_ID="{clientId}"
2805: export SECURITY_OAUTH2_CLIENT_CLIENT_SECRET="{clientSecret}"
2806: ```
2807: Then run the following before starting any servers.
2808: ```source
2809: source ~/.okta.env
2810: ```
2811: To use Okta's Sign-In Widget, you'll need to modify your app in Okta to enable an *Implicit* grant type. Log in to your account, navigate to **Applications** > **Spring OAuth** > **General** tab and click **Edit**. Enable **Implicit (Hybrid)** under **Allowed grant types** and select both checkboxes below it. Add `http://localhost:4200` under **Login redirect URIs** and click **Save**.
2812: In order for the Sign-In Widget to make requests to this application, you'll also need to configure the client URL as a trusted origin. Click **API** > **Trusted Origins** > **Add Origin**. Enter `http://localhost:4200` as the **Origin URL** and select both checkboxes under it.
2813: Change `{clientId}` and `{yourOktaDomain}` in `client/src/app/shared/okta/okta.service.ts` to match your app's values.
2814: ```typescript
2815: signIn = new OktaSignIn({
2816:   baseUrl: 'https://{yourOktaDomain}.com',
2817:   clientId: '{clientId}',
2818:   authParams: {
2819:     issuer: 'default',
2820:     responseType: ['id_token', 'token'],
2821:     scopes: ['openid', 'email', 'profile']
2822:   }
2823: });
2824: ```
2825: ### Stormpath SDK
2826: To check out the branch that uses the Stormpath SDK, run the following command.
2827: ```bash
2828: git checkout okta
2829: ```
2830: The code in the `okta` branch is described in [Secure a Spring Microservices Architecture with Spring Security, JWTs, Juiser, and Okta](https://developer.okta.com/blog/2017/08/08/secure-spring-microservices).
2831: ### Create Applications in Okta
2832: You will need to [create an Okta developer account](https://github.com/stormpath/stormpath-sdk-java/blob/okta/OktaGettingStarted.md) to configure the Spring Boot side of things. After creating an app and an access token, you should be able to set the following environment variables:
2833: ```bash
2834: export STORMPATH_CLIENT_BASEURL={baseUrl}
2835: export OKTA_APPLICATION_ID={applicationId}
2836: export OKTA_API_TOKEN={apiToken}
2837: export OKTA_AUTHORIZATIONSERVER_ID=default
2838: ```
2839: After you set these environment variables, make sure to restart your Spring Boot applications.
2840: For Angular, you'll need to create an OIDC app on Okta. Change `{clientId}` and `{yourOktaDomain}` in `client/src/app/shared/okta/okta.service.ts` to match your app's values.
2841: ```typescript
2842: signIn = new OktaSignIn({
2843:   baseUrl: 'https://{yourOktaDomain}.com',
2844:   clientId: '{clientId}',
2845:   authParams: {
2846:     issuer: 'default',
2847:     responseType: ['id_token', 'token'],
2848:     scopes: ['openid', 'email', 'profile']
2849:   }
2850: });
2851: ```
2852: **NOTE:** The value of `{yourOktaDomain}` should be something like `dev-123456.oktapreview.com`. Make sure you don't include `-admin` in the value!
2853: After making these changes, you should be able to log in with your credentials at `http://localhost:4200`.
